# ✅ LIVE — Built & Tested

## Platform & architecture
- **Two-tier app**: FastAPI (Python 3.13) backend + React 18 / Vite **PWA** frontend (installable, works partially offline).
- **Data**: SQLite in dev; a config switch targets **Postgres + pgvector** for prod (not yet exercised).
- **Auth**: JWT (HS256) + bcrypt password hashing; dept-scoped authorization on every supervisor action.
- **Face recognition**: InsightFace **buffalo_s**, 512-dim embeddings — byte-compatible with the existing camera pipeline, so a gate camera and a field selfie match the same template.
- **Time**: everything stored UTC, rendered/computed in **IST**.
- **Test coverage**: **136 backend tests** passing.

## Authentication & account security
- **Password login** (employee code + password).
- **OTP login** to mobile — 6-digit, bcrypt-hashed, 5-min TTL, attempt cap, resend cooldown (SMS provider pluggable: console in dev / Twilio stub).
- **Change password** two ways: current password **or** 2FA one-time code via **mobile OTP or email OTP**.
- **Onboarding security**: default password = employee code, forced-change flag, a persistent **ribbon nag** until changed, and a supervisor **reminder notification** if not changed within 3 days.

## Roles
- **Employee** and **Supervisor**, each with their own home screen and permissions.

## Attendance engine (core)
- Camera **entry/exit** events → per-day summaries: **present / absent** (presence-based; "late" was intentionally removed — hours-only), **hours-in-office** (pairs multiple in/out cycles), entry/exit counts.
- **Working-day / weekend** calendar config.
- **Anomaly detection**: missing entry/exit, and **two entries or two exits back-to-back** (flagged as likely camera-recognition misses).
- **Append-only corrections**: raw events are never mutated; all changes are audit-logged.

## Employee app
- **View My Attendance** (read-only): day/week/month, per-day status, hours, and the actual **in/out crossings**; summary cards (Present / Absent / Attendance %).
- **Field Attendance** (face + GPS) — shown only if the permission is granted.
- **My Profile**, **Change Password**.
- **Apply WFH/Leave** and **Holidays** — placeholder "Coming soon" screens.
- (Employee-raised **disputes were removed** by design — corrections now happen supervisor-side.)

## Field attendance (Phase 3)
- **1:1 face verification** against the employee's own enrolled template (server-side buffalo_s).
- **Active liveness**: on-device **blink detection** (MediaPipe FaceLandmarker, Apache-2.0) that **auto-captures** the selfie — no manual photo upload. Model + WASM are bundled locally and runtime-cached (works offline after first load).
- **GPS geofence**: nearest-station + radius check; **per-station radius** (default **1 km**, tweakable per row).
- **56 Hyderabad railway/MMTS stations** seeded from OpenStreetMap.
- **Decision**: inside geofence + good GPS → **approved**; outside / weak / no GPS → **pending** ("not at a station — X km from …") routed to supervisor.
- **Mandatory check-in/check-out pairing** enforced.
- **Audit selfies** stored **60 days** (purge helper).
- **Offline capture + sync (3d)**: scans taken with no signal are queued in **IndexedDB** (selfie + GPS + direction + **capture timestamp**) and **auto-replay** to the server when connectivity returns (server runs the real match/geofence at sync; capture time is preserved). Pending-count banner + "Sync now".

## Supervisor app
- **View My Attendance**.
- **Employee Attendance** (dashboards): two-level **searchable department/employee filter**; per-employee daily drill-in.
- **Attendance editing** (audit-friendly): **edit** any crossing's time, **delete** a crossing (tombstone), **add** a new entry/exit, and **day-level status override** (e.g. absent → present). New crossings are rejected only if they introduce a *new* sequence conflict.
- **Analytics dashboard**:
  - KPI cards (attendance %, present, absent, hours, staff count, field-pending) that **react to all filters**.
  - **6 interactive charts** (Recharts): attendance-% trend, present-vs-absent, by-department, camera/field/manual split, hours-by-employee, lowest-attendance.
  - **Filters**: date range, department, and a **staff-type multiselect** (Field / Supervisors / Office / All).
  - **Data tables** view (by-department + employee roster) for exact numbers.
  - **Export**: per-visual **CSV / PNG**, plus whole-dashboard **Excel / PDF / PPT**.
- **Onboard Employee**: create with **department + reporting supervisor + role + field-scan permission**, then **face enrollment** (multi-photo → averaged embedding → cloud + edge gallery).
- **Employee Settings**: fully editable anytime — name, phone, email, blood group, role, department, reporting supervisor, home station, field-scan permission.
- **Field Approvals**: queue of uncertain-location scans with the **audit selfie**, distance, GPS accuracy → **Approve / Reject** (rejected scans stop counting).
- **Notifications**: password reminders + camera-error alerts.
- **My Profile**, **Change Password**.

## Edge / pipeline integration
- **Gallery pull** endpoint (`GET /edge/gallery`, incremental via `?since`, base64 embeddings) + a stdlib **edge pull client**; event **push client** with offline queue.

## Demo data

## ⚠️ Two real audit flags

### 1. InsightFace **pretrained model weights** (`buffalo_s`) — the big one
- The **InsightFace code is MIT**, but its **pretrained models** (the `buffalo_*` / `antelopev2` families) are licensed **for non-commercial / academic research use only**.
- Your app uses `buffalo_s` for face embeddings — so a **commercial/government production deployment could fail an audit** on the *model*, even though the code is fine.
- **Important context:** this is **inherited from your existing camera pipeline** (which already uses `buffalo_s`) — it's a pre-existing org decision, not something new this project introduced. But it must be on the radar.
- **Remediation options:** obtain a commercial face-recognition model license, train/fine-tune your own weights, or swap to a commercially-licensed model. (Because we kept embeddings pipeline-compatible, whatever the pipeline resolves, this app inherits automatically.)

### 2. OpenStreetMap station coordinates — **ODbL 1.0**
- The 56 Hyderabad station coordinates were sourced from **OpenStreetMap**, which is **ODbL** + requires **"© OpenStreetMap contributors"** attribution; ODbL's share-alike can attach to a *derived database*.
- Risk is low (small set of factual lat/longs), but **attribution is required**.
- **Remediation (easy):** add an OSM attribution line where stations are shown/admin-managed, **or** replace the seed with coordinates from an authoritative railway source you own (then there's no ODbL at all).

## 🟡 One minor thing
- **`opencv-python`** wrapper is Apache-2.0 but its wheel bundles **FFmpeg (LGPL-2.1)**. LGPL via dynamic linking is generally fine, but on a **headless server** the cleaner choice is **`opencv-python-headless`** (same API, no GUI/codec surface) — removes the question entirely.
- The **MediaPipe `face_landmarker.task`** model (liveness only, not identity) is published under **Apache-2.0** per its model card — fine, but worth confirming the model card at pin time.

## Bottom line
- **Libraries: you're clean** — nothing copyleft/GPL, nothing that forces source disclosure.
- **You could get flagged in an audit on the InsightFace pretrained weights** (non-commercial license) — resolve at the **pipeline/model level**; the app follows.
- **OSM data needs attribution** — quick to fix.

> This is an engineering good-faith summary, not legal advice — your legal/procurement team should sign off on the InsightFace model license specifically, since that's the one with commercial-use restrictions.
