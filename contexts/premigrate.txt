# ✅ LIVE — Built & tested

## Platform & architecture
- **Two-tier app**: FastAPI (Python 3.13) backend + React 18 / Vite **PWA** frontend (installable to home screen, works partially offline).
- **Database**: SQLite in dev; one config switch (`DATABASE_URL`) targets **Postgres + pgvector** for prod. Same SQLAlchemy code runs on both — see `database.py`.
- **Face recognition**: InsightFace **`buffalo_s`**, 512-dim L2-normalized embeddings, stored as raw float32 bytes — **byte-compatible with the existing camera pipeline**, so a gate camera and a phone selfie match against the same template. Matching is a plain cosine dot product.
- **Time model**: everything stored in **UTC**, rendered and computed in a configurable display timezone (**IST / Asia-Kolkata**). Attendance "days" and working-day logic are computed in local time.
- **Config-driven**: every tunable (thresholds, shift times, geofence radius, retention windows, camera direction map) lives in `config.py` / `.env` — no magic numbers in code.
- **API surface**: ~74 endpoints across 11 routers (auth, attendance, field, employees, supervisor, assistant, analytics, disputes, events, edge, notifications).
- **Test coverage**: **~173 backend tests** passing across 15 suites (auth, attendance engine, disputes, anomalies, OTP, onboarding, password/notifs, analytics, events, field, settings, signup, EA delegation, dept-scoping).

## Roles & access model (4 roles)
1. **Employee** — own attendance, profile, optional field scan.
2. **Supervisor** — full management, **scoped to their own department** on every action.
3. **Chief manager** (`chief`) — supervisor-level powers but **across all departments**; default views include supervisors alongside employees; exempt from the department-scope guard.
4. **Executive Assistant** (`assistant` / EA) — offloads grunt work: **global** sign-up approval queue + **delegated tasks** from their supervisor.
- Authorization is enforced server-side per request via `require_supervisor` / `require_assistant` guards in `deps.py`, plus explicit department-scope checks so a supervisor can't widen scope via query params (there's a dedicated test for that).

## Authentication & account security
- **Password login** (employee code + password), JWT (HS256) + bcrypt hashing.
- **OTP login to mobile** — 6-digit, **bcrypt-hashed** (never stored plaintext), 5-min TTL, attempt cap, resend cooldown. SMS provider pluggable (console in dev / Twilio stub for prod).
- **Change password** two ways: current password **or** a 2FA one-time code delivered via **mobile OTP or email OTP**.
- **Onboarding security**: default password = employee code, `must_change_password` forced-change flag, a persistent **ribbon nag** in the UI until changed, and a supervisor **reminder notification** if not changed within N days (configurable).
- **Phone normalization** and anti-spam cooldown on OTP requests.

## Attendance engine (core)
- Camera **entry/exit** events → per-day summaries: **present / absent** (presence-based — "late" was intentionally removed, hours-only), **hours-in-office** (correctly pairs multiple in/out cycles, e.g. lunch), and **entry/exit counts**.
- **Working-day / weekend** calendar (configurable weekday set); weekends never show "absent".
- **Future-day handling**: an upcoming working day shows "upcoming," not "absent," and is excluded from stats.
- **Anomaly detection**: missing entry or exit, and **two entries or two exits back-to-back** (flagged as likely camera-recognition misses).
- **Append-only corrections**: raw `attendance_events` are **never mutated**. Corrections are new linked rows (supersede via `replaces_event_id`; deletes are **tombstones** via `voided`) — fully audit-traceable.
- **Direction resolution**: uses the edge-supplied `direction`, falling back to a configurable `camera_label → entry/exit` map.

## Employee app
- **View My Attendance** (read-only): day / week / month, per-day status, hours, and the actual **in/out crossings**; summary cards (Present / Absent / Attendance %).
- **Field Attendance** (face + GPS) — shown only if the permission is granted.
- **My Profile** (view + edit name/phone/email/blood group, avatar upload), **Change Password**.
- **Apply WFH/Leave** and **Holidays** — placeholder "Coming soon" screens (table exists; workflow parked).
- **Self sign-up**: a prospective user can register (with mobile OTP verification) → creates a **`pending`** account that **cannot log in** until an EA approves it.
- (Employee-raised **disputes exist in the model/tests** but were removed from the employee UI by design — corrections now happen supervisor/EA-side.)

## Field attendance (face + GPS)
- **1:1 face verification** against the employee's own enrolled template (server-side `buffalo_s`), configurable match threshold (stricter than the camera).
- **Active liveness**: on-device **blink detection** (MediaPipe FaceLandmarker, Apache-2.0) that **auto-captures** the selfie — no manual upload. Model + WASM bundled locally and runtime-cached (works offline after first load).
- **GPS geofence**: nearest-station + radius check (Haversine); **per-station radius** (default 1 km, tweakable per row).
- **56 Hyderabad railway/MMTS stations** seeded from OpenStreetMap.
- **Decision logic**: inside geofence + good GPS accuracy → **approved**; outside / weak / missing GPS → **pending** ("not at a station — X km from …") routed to a supervisor/EA.
- **Mandatory check-in/check-out pairing** enforced (can't exit without entry, can't double check-in); status endpoint suggests the next expected direction; anti-double-punch time window.
- **Audit selfies** stored for a configurable retention window (default 60 days) with a purge helper.
- **Offline capture + sync**: scans taken with no signal are queued in **IndexedDB** (selfie + GPS + direction + capture timestamp) and **auto-replayed** to the server on reconnect — the server runs the *real* match + geofence at sync time, preserving the original capture time. Pending-count banner + "Sync now."
- In non-prod, the response returns the match similarity for debugging (a flag to disable in prod).

## Supervisor app
- **View My Attendance** (own record).
- **Employee Attendance dashboards**: two-level **searchable department/employee filter**; per-employee daily drill-in. Department-scoped (chief sees all).
- **Attendance editing** (audit-friendly): **edit** a crossing's time, **delete** a crossing (tombstone), **add** a new entry/exit, and **day-level status override** (e.g. absent → present). New crossings are rejected only if they introduce a *new* sequence conflict.
- **Anomalies view**: list of days with missing/duplicate crossings.
- **Field Approvals**: queue of uncertain-location scans with the **audit selfie**, distance, and GPS accuracy → **Approve / Reject** (rejected scans stop counting).
- **Onboard Employee**: create with **department + reporting supervisor + role + field-scan permission**, then **face enrollment** (multi-photo → averaged embedding → pushed to cloud + edge gallery). Quality gating rejects blurry/off-angle photos.
- **Employee Settings**: fully editable anytime — name, phone, email, blood group, role, department, reporting supervisor, home station, field-scan permission.
- **Disputes review** (server-side): approve/reject with resolution notes; approval writes an override that fixes the day.
- **Excel export** of attendance (openpyxl).
- **Notifications**: password reminders + camera-error alerts.
- **My Profile**, **Change Password**.

## Executive Assistant (EA) — delegation system
- **Global onboarding queue**: any EA can clear **any** department's pending sign-ups (approve / reject / attach onboarding photos), with an **"already handled" guard** to prevent double-processing.
- **Delegated tasks** from their supervisor (private to the assigned EA), two kinds:
  - **`field_approval`** — decide one pending field scan (auto-completes if the underlying event leaves "pending").
  - **`attendance_edit`** — fix one employee's day (edit/add/delete crossings + override), closed by an explicit **"Mark complete"**; **requires a comment**.
- Supervisor can **recall** a delegated task (removes it from the EA's list).
- EA has its own **profile**, task list, and per-task day view + selfie view.

## Chief manager
- Same toolset as a supervisor but **cross-department**: any department's overview, any employee's summary, all supervisors, all field approvals; analytics default to org-wide and include supervisors in headcounts.

## Notifications (per-recipient inbox)
- Stored, append-only alerts delivered to a specific person (employee, EA, supervisor).
- Types include **field_pending / field_approved / field_rejected**, password reminders, and camera-error alerts. `is_read` toggling + "mark read" endpoint.

## Analytics dashboard (supervisor/chief)
- **KPI cards** (attendance %, present, absent, hours, staff count, field-pending) that **react to all filters**.
- **6 interactive Recharts visuals**: attendance-% trend, present-vs-absent, by-department, camera/field/manual **source split**, hours-by-employee, lowest-attendance.
- **Filters**: date range, department, and a **staff-type multiselect** (Field / Supervisors / Office / All).
- **Trend granularity**: day or month.
- **Data tables** view (by-department + employee roster) for exact numbers.
- **Export**: per-visual **CSV / PNG**, plus whole-dashboard **Excel / PDF / PPT** (jsPDF + pptxgenjs).

## Edge / pipeline integration
- **Gallery pull** (`GET /edge/gallery`, incremental via `?since`, base64 embeddings) protected by a shared **edge API key**; a stdlib **edge pull client** (`pull_gallery.py`).
- **Event push** (`POST /events`, edge-key protected) + an **edge push client with an offline retry queue** (`push_events.py`).

## Data model (tables)
`departments`, `stations`, `persons` (extended with web columns + lifecycle status), `face_embeddings`, `attendance_events` (extended with source/direction/GPS/review/audit columns), `attendance_overrides`, `disputes`, `leave_requests`, `otp_challenges`, `delegated_tasks`, `notifications`. Face templates never destructively overwrite pipeline data.

## Demo / seed data
- Seeds for departments, supervisors, and employees with a month of mixed camera + field attendance for realistic analytics; station seed (56 stations); EA and password seeds; several additive migration scripts (`migrate_ea`, `migrate_phase3`, `migrate_signup`).
